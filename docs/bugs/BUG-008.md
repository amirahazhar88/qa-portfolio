# BUG-008: `favorited` is true for every reader once anyone has favorited the article

| | |
|---|---|
| **Status** | Open |
| **Severity** | High (a reader who never favorited an article is shown it as favorited, with an "Unfavorite" button) |
| **Priority** | P1 |
| **Found by** | API test `test_an_anonymous_reader_sees_the_count_but_not_favorited` |
| **Found on** | 2026-11-10 |
| **Component** | API article responses (`GET /api/articles`, `GET /api/articles/{slug}`) |

## Steps to reproduce
1. User A publishes an article. Nobody has favorited it (`favorited: false` for everyone).
2. User B favorites it.
3. Read the article as **anonymous**, and as a third user **C** who never favorited it.

## Expected
`favorited: false` for anonymous and for C. Only B sees `true`. `favoritesCount` is 1 for everyone.

## Actual
`favorited: true` for **anonymous and for C**, as soon as B has favorited. The article list shows the same.

## Evidence
Before B favorites: anonymous `false`. After: anonymous `true`, C `true`.

## Suspected cause
The query appears to test "does any favorite row exist for this article" rather than "does this reader's favorite exist".

## Not caught by the UI tests so far
The UI favorites tests use a single reader per article, so they cannot see this. A two-reader UI test is worth adding.

## Automation
`api-tests/.../test_favorites.py` (two `xfail` tests, strict).
