# BUG-009: `following` is true for anonymous callers once anyone follows the user

| | |
|---|---|
| **Status** | Open |
| **Severity** | Medium (wrong state shown to signed-out visitors; the signed-in case is correct) |
| **Priority** | P2 |
| **Found by** | API test `test_following_is_visible_to_the_follower_only` |
| **Found on** | 2026-11-10 |
| **Component** | API `GET /api/profiles/{username}` and `author.following` in article responses |

## Steps to reproduce
1. User B follows user A.
2. `GET /api/profiles/A` **with no token**.

## Expected
`following: false` (an anonymous caller follows nobody).

## Actual
`following: true`. `author.following` in `GET /api/articles?author=A` is also `true` for anonymous callers.

## Evidence
A signed-in user who does not follow A correctly gets `false`; only the anonymous path is wrong.

## Suspected cause
Same family as BUG-008: with no signed-in user, the "is followed" check is not tied to a specific reader.

## Automation
`api-tests/.../test_profiles.py::TestFollow::test_an_anonymous_visitor_does_not_see_following` (`xfail`, strict).
