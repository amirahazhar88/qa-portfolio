# BUG-001: Filtered article lists skip too many rows when `offset` > 0 (pagination broken)

| | |
|---|---|
| **Status** | Open |
| **Severity** | High (a major feature is broken: pages after the first show no articles) |
| **Priority** | P1 |
| **Found by** | Automated test `tests/feed.spec.ts` (page 2 of a tag-filtered feed) |
| **Found on** | 2026-11-10 |
| **Component** | API: `GET /api/articles` (and the feed query) |
| **Environment** | Local Docker stack, API on `:3100`, frontend on `:8080`, MySQL 8 |

## Summary
`GET /api/articles?limit=10&offset=10&tag=<tag>` returns no articles even though `articlesCount` says 11 match. The UI therefore shows an empty page 2 for any filtered feed with more than 10 articles.

## Steps to reproduce
1. Register a user and create 11 articles that share one tag (e.g. `pgt1`).
2. `GET /api/articles?tag=pgt1&limit=10&offset=0`
3. `GET /api/articles?tag=pgt1&limit=10&offset=10`

(UI route: open `/tag/pgt1`, then click page "2".)

## Expected
- Step 2 returns 10 articles, `articlesCount: 11`.
- Step 3 returns the remaining **1** article, `articlesCount: 11`.
(`offset` is the number of items to skip, as the RealWorld API spec and the frontend use it.)

## Actual
- Step 3 returns **0** articles with `articlesCount: 11`; the UI page 2 is empty.

## Evidence (11 articles with one tag)

| Request | Returned | Expected |
|---|---|---|
| `limit=20&offset=0` | 11 | 11 |
| `limit=10&offset=0` | 10 | 10 |
| `limit=10&offset=1` | **1** | 10 |
| `limit=10&offset=5` | **0** | 6 |
| `limit=10&offset=10` | **0** | 1 |
| `limit=5&offset=5` | **0** | 5 |
| `limit=5&offset=10` | **0** | 1 |
| `author=<user>&limit=10&offset=10` | **0** | 1 |

## Suspected cause
`newsclip/api/packages/core/database/DbArticle/DbArticle.ts` (line ~148):

```ts
query = query.offset(offset * (limit ?? 1));
```
`offset` is multiplied by `limit`, as if it were a page number. With `limit=10`, `offset=10` becomes a SQL offset of 100, and `offset=1` becomes 10 (which matches the table above: 1 row returned out of 11). The same pattern appears near line 282.

## Impact
Users cannot reach any article beyond the first page of a filtered feed (by tag, author or favorites). The pager still renders, because `articlesCount` is correct.

## Automation
`tests/feed.spec.ts` › "page 2 of a long feed shows the remaining article" is marked `test.fail()` and linked to this bug. The suite stays green while the bug is open. When the bug is fixed the test **starts failing on purpose**, which is the signal to remove `test.fail()`.
