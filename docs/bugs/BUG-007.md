# BUG-007: Deleting a comment returns 200 but the comment is not removed

| | |
|---|---|
| **Status** | Open |
| **Severity** | High (data the user asked to remove stays visible to everyone) |
| **Priority** | P1 |
| **Found by** | API test `test_the_author_can_delete_their_comment`, then confirmed in the database |
| **Found on** | 2026-11-10 |
| **Component** | API `DELETE /api/articles/{slug}/comments/{id}` |

## Steps to reproduce
1. User A publishes an article; user B posts a comment on it.
2. As B: `DELETE /api/articles/{slug}/comments/{id}` -> **200**.
3. `GET /api/articles/{slug}/comments`

## Expected
The comment is gone: `count: 0`.

## Actual
The comment is still listed. In MySQL its `record_status` is still `active`. Deleting again also returns 200.

## Why the UI hides it
The frontend removes the comment from the screen without confirming with the server, so the UI test "a user can delete their own comment" passes. After a **reload** the comment comes back. Only a reload-based check (or an API test) exposes it.

- `ui-tests/tests/comments.spec.ts` › "a deleted comment stays gone after a reload" (`test.fail()`)
